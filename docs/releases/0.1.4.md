## Changes

- Keep `discussion_read` available for a locally owned running turn during the
  app-server's empty-rollout and unsupported-history startup window. Cover both
  `discussion_start` and `discussion_reply`, retaining partial and final output
  without replaying inference.
- Preserve unrelated errors, historical turn/cursor boundaries, working legacy
  inline history, and backend checks for work started by another client.
- Include the fix from [PR #14](https://github.com/smallmiro/codex-discussion-mcp/pull/14),
  resolving [issue #13](https://github.com/smallmiro/codex-discussion-mcp/issues/13).

## Publication Path

The release-triggered [OIDC run](https://github.com/smallmiro/codex-discussion-mcp/actions/runs/41181929503)
passed tests, build, and exact tarball installation verification, but npm rejected
publication with `E404`. Actual OIDC publication remains unverified.

After confirming that `0.1.4` was absent from the public registry, the existing
`bootstrap-publish.yml` workflow was dispatched against `v0.1.4` with version
input `0.1.4`. The [bootstrap run](https://github.com/smallmiro/codex-discussion-mcp/actions/runs/41181996262)
passed every step and published using the existing `NPM_TOKEN` repository Secret.
Credential values were not read or exposed. Public version metadata, the tarball,
and the `latest` tag propagated separately; all were verified afterward.

## Update

For a global npm installation:

```bash
npm install -g @mirolab/codex-discussion-mcp@0.1.4
```

For project-local installations, update the dependency in that project. Change
version-pinned `npx` MCP configurations to `0.1.4`, then reconnect the MCP server.
Refresh separately copied skills independently of the npm package.

The README's Skills CLI installation instructions were added after the immutable
`v0.1.4` source tag and are available on `main`; they do not change this tarball.
